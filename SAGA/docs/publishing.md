# Prepare a thesis repository

The repository is prepared locally, not published to an account automatically. Choose the repository owner/name and visibility, add author/thesis details, and select an authorized software license before making it public. No legal license text is assigned by this draft. Public visibility alone does not grant reuse rights. Check institutional and collaborator ownership before choosing a license.

## Contents to keep

Commit the shared `saga/` source, small presets, submission/analysis scripts, compact historical example, documentation and tests. Keep models, run trees, caches, trajectories, raw training data, credentials and private paths out of git. The included `.gitignore` covers common generated files; inspect the staged diff before committing.

Replace this README's pending author/citation paragraph and add a valid `CITATION.cff` once actual author names, title, repository URL and publication/thesis details are known. Do not invent a DOI. Cite MACE, ASE and scikit-learn as well as the SAGA work. After a successful real example with the intended model, record the environment and add the resulting compact outputs.

## Upload from the extracted directory

Create an empty repository on GitHub without adding a second README. Then run, replacing the example URL:

```bash
git init -b main
git add .
git diff --cached --stat
git diff --cached
git commit -m "Prepare SAGA research release"
git remote add origin https://github.com/OWNER/REPOSITORY.git
git push -u origin main
```

The actual remote URL is intentionally not filled in. Git author identity and GitHub authentication must be configured in the user's own environment. GitHub Actions runs automatically after upload if enabled.

## Thesis version

Once the release is reviewed and its small MACE example is verified, tag the exact commit used in the thesis. Archive that release through an appropriate research repository if a DOI is required. A thesis figure generated with a historical protocol should cite that specific archived protocol/data, not claim it was generated by the current version.

The release does not include the full NEB or vibration workflows. Add those separately only after their source, run interfaces and data provenance have been checked.
